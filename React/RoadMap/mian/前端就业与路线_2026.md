# 个人前端就业与进阶路线（2026）

> 制定日期：2026-07-14  
> 近期目标：尽快获得 React/前端开发岗位  
> 长期定位：先以 React/TypeScript 业务交付能力获得正式前端经历，再逐步用数据可视化、Three.js/WebGL 和 UI 工程能力形成差异化

## 1. 当前能力判断

根据现有简历，你已经不是“刚学完 React”的阶段，而是已经达到可以投递初级前端岗位、需要提高面试转化率的阶段。

### 已有优势

- 计算机本科，GPA 3.47/4、专业 TOP 15%，且有英语六级。
- 已有 3 个独立项目，不缺普通 CRUD 项目：
  - TaskFlow：Next.js、TypeScript、Appwrite、Zustand、ECharts、表单校验、URL 状态与测试。
  - RedditLike：React 19、Convex、Clerk、实时数据、鉴权、搜索、上传和并发计数。
  - U-s-cinema：React、TypeScript、TMDB API、请求封装、迁移和异常状态。
- 接触过 Vue、Figma、ECharts、Node.js/MySQL，能够覆盖一部分国内前端岗位要求。
- 已经有接口建模、状态边界、异常处理和响应式意识，不只是会拼页面。

### 当前最影响求职的缺口

1. **没有正式前端工作经历。** 项目必须用在线演示、测试、性能数据和清晰讲解来提高可信度。
2. **测试深度不足。** 简历目前主要能证明工具函数测试，还不能证明关键用户流程可靠。
3. **缺少量化结果。** 需要补充 Lighthouse/Core Web Vitals、包体积、测试数量、关键操作耗时等可验证指标。
4. **基础面试表达仍需系统化。** JS、浏览器、网络、React 和 TypeScript 必须能脱离项目口述。
5. **技术面较宽，但容易被追问穿透。** 简历上的 Next.js、鉴权、实时查询、Zustand、ECharts 等都要能解释原理与取舍。
6. **特色方向还没有代表作。** 3D、可视化和 UI 都有兴趣，但目前尚未形成一个招聘方能记住的作品。
7. **2025 届但尚无正式前端经历。** 当前时间是 2026 年，招聘方可能关注毕业后的状态，需要用持续开发、投递记录和清晰的到岗状态减少疑虑。

### 立即核对的简历问题

- “闲置物品互换平台”的实际时间是 `2023.10 - 2024.04`，当前简历写法正确；此前关于起止时间倒置的判断有误，不需要修改。
- 在个人简介或基本信息中明确“2025 届、可尽快到岗”，减少招聘方对当前状态的猜测。
- 每个主项目应提供在线地址、演示账号或无登录演示模式；只有 GitHub 链接会降低查看率。
- 不再继续增加“熟悉/了解”的技术名词。无法连续回答 3 个追问的内容，应降级表述或删除。
- 项目描述优先保留难点、方案、约束和结果，压缩功能清单。
- TaskFlow 和 RedditLike 作为核心项目；U-s-cinema 压缩为 2-3 条，校园项目准确区分“负责”“参与”和“协助”。

## 2. 求职定位与技术优先级

### 推荐定位

> 能独立交付 React/TypeScript 业务应用，熟悉 Next.js、实时数据与工程化，并具备数据可视化和 Web 3D 能力的前端工程师。

近期优先岗位：

1. React / TypeScript 初级前端开发。
2. 中后台、SaaS、内容社区、数据产品前端。
3. 数据可视化、数字孪生、工业互联网方向的初级前端。
4. 同时投递 Vue 3 中后台与业务岗位，并用 1-2 周补齐常见语法、生态和 React/Vue 差异；不再专门做一个 Vue CRUD 项目。

暂时不要把自己包装成“纯 WebGL/3D 工程师”。纯 3D 岗位数量较少，对图形学、GLSL 和性能经验要求更高。更稳妥的策略是先用 React/TypeScript 获得工作，再用 3D/可视化扩大岗位范围和议价能力。

### 2026 技术优先级

| 层级 | 技术 | 你的策略 |
| --- | --- | --- |
| 就业核心 | JavaScript、TypeScript、HTML、CSS、React、Git、HTTP | 每天复习，必须能口述和手写 |
| 工程核心 | Next.js、Vite、React Router、TanStack Query、Zustand、React Hook Form、Zod | 在 TaskFlow 中证明真实使用和取舍 |
| 质量核心 | Vitest、Testing Library、Playwright、ESLint、CI、Core Web Vitals、a11y | 未来 4 周重点补齐 |
| 国内岗位兼容 | Vue 3、Pinia、Vue Router、Element Plus | 1-2 周集中补齐，达到能读、能改、能完成常见业务页面并回答差异 |
| 可视化优势 | ECharts、D3、Canvas/SVG、数据建模 | ECharts 负责业务图表，D3 负责定制表达 |
| 3D 优势 | Three.js、React Three Fiber、Drei、Blender、glTF、GLSL | 先 Three.js 原理，再 R3F 工程化 |
| UI 优势 | Figma、设计系统、Storybook、响应式、可访问性 | 作为工程能力，不转为纯 UI 设计师 |
| 观察项 | WebGPU、AI 流式 UI、Turborepo、Web Worker/WASM | 有具体项目需求后再学，不作为近期门槛 |

WebGPU 值得关注，但不是求职冲刺期任务。进入稳定面试流程或拿到 offer 后，再从 Three.js 的场景、相机、材质、光照、渲染循环和资源管理开始，之后了解 Three.js 的 WebGPU 路径及 WGSL。

## 3. 第一阶段：7 天求职启动

目标：不再等待“学完”，一周内让材料进入可投递状态，并开始获取真实市场反馈。

### 任务

- 核对简历日期、链接和所有无法验证的表述，保持一页或最多两页。
- 在简历中明确“2025 届、可尽快到岗”，并准备一句话说明毕业后的持续学习与项目开发经历。
- 确保 TaskFlow、RedditLike 至少有两个可访问的在线演示。
- 为每个项目 README 补齐：截图、演示地址、架构、运行方式、环境变量示例、关键取舍、测试命令。
- GitHub 置顶 TaskFlow、RedditLike、U-s-cinema；清理无说明的练习仓库。
- 准备 60 秒自我介绍、3 分钟 TaskFlow 介绍、5 分钟项目深挖版本。
- 建立投递表：公司、岗位、技术要求、日期、进度、反馈、暴露出的知识缺口。
- 本周开始投递 20-30 个匹配度较高的岗位，覆盖 React、Vue 3、中后台、SaaS、行业软件及合理范围内的外包/驻场机会，不海投完全不匹配职位。

### 验收

- 招聘方打开简历后，两次点击内可以看到在线项目。
- 陌生人能在 5 分钟内按 README 运行项目。
- 你能解释 TaskFlow 的认证链路、状态分层、URL 协议、异常处理和一个技术取舍。

## 4. 第二阶段：第 2-4 周，就业能力加固

目标：用一个主项目证明工程深度，同时提高笔试与技术面通过率。

### TaskFlow 只做高价值升级

不要重写项目，也不要为了热门库强行换技术栈。优先完成：

1. **端到端测试**：使用 Playwright 覆盖登录/演示模式、创建任务、筛选、跨视图跳转和删除确认。
2. **组件测试**：使用 Testing Library 覆盖表单校验、空状态、错误状态和筛选交互。
3. **性能证据**：记录优化前后的 Lighthouse、LCP、CLS、INP、首屏资源和主要包体积。
4. **可访问性**：键盘导航、焦点管理、表单标签、弹窗语义、颜色对比度和 reduced motion。
5. **错误治理**：错误边界、请求失败重试、超时、无权限、离线或服务不可用状态。
6. **CI**：每次提交运行 lint、typecheck、test、build 和关键 E2E。

TanStack Query 不必为了写进简历而强行加入。如果 TaskFlow 当前由 Zustand 管理远程任务数据，必须能解释缓存、同步、失效、乐观更新和错误回滚；如果这些逻辑已经明显复杂，再迁移服务端状态到 TanStack Query，Zustand 只保留跨页面 UI 状态。

### 面试基础清单

每天 60-90 分钟，按“先口述，再写最小示例，最后回到项目”学习：

- JavaScript：作用域、闭包、原型链、`this`、事件循环、Promise、错误传播、模块、深浅拷贝。
- TypeScript：联合类型、类型收窄、泛型、条件类型、映射类型、`unknown` 与 `never`。
- React：渲染触发、状态快照、Effect 边界、闭包陷阱、Context、受控组件、性能优化。
- 浏览器：DOM/CSSOM、渲染流水线、事件传播、存储、同源策略、缓存和安全基础。
- 网络：HTTP 方法、状态码、缓存、Cookie、CORS、HTTPS、WebSocket/SSE。
- CSS：盒模型、BFC、Flex/Grid、层叠、定位、响应式、动画性能。

### Vue 3 兼容模块（集中 1-2 周）

- Composition API：`ref`、`reactive`、`computed`、`watch`、生命周期与组件通信。
- Pinia、Vue Router、表单、列表、弹窗和接口请求等常见中后台流程。
- 能解释 Vue 与 React 在响应式模型、更新机制、状态管理和组件组织上的主要差异。
- 使用现有校园项目或一个小页面完成复习验证，不新建大型 Vue CRUD 项目。

### 每周硬指标

- 精准投递 20-30 个岗位，并记录回复率、约面率、拒绝原因和重复出现的岗位要求。
- 2 次模拟技术面试，至少 1 次录音复盘。
- 1 次项目改进发布。
- 1 篇短项目记录，内容可以是 bug、取舍、性能或测试，不追求长文。

## 5. 第三阶段：第 5-8 周，继续求职并按反馈加固

目标：求职、面试基础和 TaskFlow 质量仍占主要时间。只有当面试反馈没有暴露更紧急的 JS、React、Vue 或项目表达问题时，才把可视化作为副线推进。

### 学习顺序

1. 数据清洗、指标口径、时间序列、分类与聚合。
2. 图表选择、比例尺、颜色、标签、tooltip、空数据和异常值。
3. ECharts 的 dataset、encode、联动、缩放、性能和响应式。
4. 有明确的定制交互需求时，再学习 SVG、Canvas 的差异以及 D3 的 scale、axis、shape 和 interaction。
5. 键盘访问、文本摘要、移动端替代视图和色觉友好。

### 条件性项目产出

在求职主线任务按周完成的前提下，对 TaskFlow 的 Stats 页面做一次可验证升级，而不是新开仓库：

- 周/月完成趋势、逾期风险、优先级分布、任务流转效率。
- 图表与 URL 筛选联动，刷新和分享后状态可恢复。
- 点击图表可进入对应任务集合。
- 若 ECharts 无法合理完成某个定制表达，再选择一个局部图表使用 D3；不为技术展示强行引入 D3。
- 补一份指标口径说明，解释“完成率”“逾期”“风险”等如何计算。

### 条件验收

- 能解释为什么选择某种图表，而不是只解释 API 配置。
- 能说明 SVG、Canvas 和 WebGL 在数据量、交互和可访问性上的取舍。
- 能处理零值、缺失值、极端值、长标签和移动端布局。

如果这一阶段面试反馈集中在基础知识、Vue、项目可信度或表达能力，则本阶段验收改为：完成对应补强、更新简历或项目，并验证下一轮面试是否改善。D3 不作为前 8 周的硬性验收项。

## 6. 第四阶段：进入稳定面试流程或拿到 offer 后，Three.js + Blender 入门

你提到的“3d.js”通常指 **Three.js**。这部分不再绑定固定的第 9-12 周：只有当求职主线稳定、每周投递和面试复盘都能完成时才开始。先建立图形基础和资产管线，不急着做大型数字孪生。

### 学习顺序

1. Three.js：Scene、Camera、Renderer、坐标系、Object3D、Geometry、Material、Texture。
2. 光照、阴影、OrbitControls、Raycaster、动画循环、资源加载与销毁。
3. Blender：基础建模、法线、UV、材质、灯光、低多边形优化。
4. glTF/GLB 导出：尺寸、坐标、纹理、动画、压缩和加载验证。
5. React Three Fiber：Canvas、Hooks、Drei、Suspense、事件和 React 状态边界。
6. 性能：draw call、纹理尺寸、InstancedMesh、LOD、按需渲染、资源释放。

### 两个最小作品

- 作品 1：相机、灯光、材质实验室，并记录核心概念和资源释放方式。
- 作品 2：加载一个自己在 Blender 制作的 GLB，完成热点点击、材质切换和基础性能记录。

每个作品先控制在 2-4 天的核心开发量。完成后再根据兴趣和目标岗位决定是否扩展产品配置器或性能对比页。

## 7. 第五阶段：正式工作稳定后或求职主线不受影响时，差异化旗舰作品

推荐把你的三个兴趣合并为一个作品：**交互式 3D 运营数据空间**。

### 推荐题材

选择一个能获得公开数据、场景规模可控的主题，例如：

- 园区能耗与设备状态。
- 城市公共交通或空气质量。
- 个人工作效率与时间分配。
- 博物馆/展品浏览与参观数据。

### 技术构成

- React + TypeScript + Vite 或 Next.js。
- Three.js / React Three Fiber / Drei 负责 3D 场景。
- Blender 负责低多边形模型和 glTF 资产管线。
- ECharts 负责标准业务图表，D3 负责自定义时间轴或空间映射。
- Playwright 覆盖筛选、热点、时间切换和降级视图。
- Figma 先完成信息架构、关键页面和组件状态，再进入开发。

### 必须有的产品能力

- 2D 数据面板与 3D 对象联动。
- 时间范围、指标和对象筛选可进入 URL。
- 加载进度、错误状态、空数据和无 WebGL/低性能设备降级方案。
- 桌面端完整体验；移动端提供可用的 2D 替代视图，不强塞完整 3D。
- 明确的数据来源、指标口径、性能预算和无障碍文本摘要。

### 性能预算

- 首屏不加载非必要 3D 资源。
- 模型、纹理和第三方包按需加载。
- 记录 FPS、draw calls、三角面数量、纹理占用和加载体积。
- 页面离开后释放 geometry、material、texture 和事件监听。
- 数据计算较重时再使用 Web Worker；不要提前引入 WASM。

这个项目的价值不是“画面炫”，而是证明你能把数据、交互、3D 性能和产品可用性组合起来。

## 8. UI 设计学习路线

你的目标应是“设计敏感的前端工程师”，而不是在求职冲刺期转成纯 UI 设计师。

### 第 1 层：视觉基础（与第二阶段并行）

- 间距系统、排版层级、对齐、对比、颜色和密度。
- 表单、表格、导航、弹窗、空状态、错误状态和加载状态。
- 每周选一个成熟产品页面，先在 Figma 分析，再用代码还原。

### 第 2 层：组件与设计系统（第 2-3 个月）

- Figma Auto Layout、Components、Variants、Variables。
- Design Token：颜色、间距、字号、圆角、阴影和动效。
- Storybook 展示组件状态，并加入可访问性检查。
- Tailwind CSS、shadcn/ui 可以学习，但必须能解释最终 CSS 和可访问性，不能只会复制组件。

### 第 3 层：数据与 3D 界面

- 高信息密度布局、图表标注、过滤器、图例和跨视图联动。
- 3D 场景中的热点、选择、聚焦、加载反馈和键盘替代操作。
- 动效只用于反馈、空间关系和状态变化，并支持 `prefers-reduced-motion`。

## 9. 每周时间安排

按每周 30 小时：

| 内容 | 第 1-4 周 | 第 5-8 周 | 主线稳定后 |
| --- | ---: | ---: | ---: |
| 投递、沟通、复盘 | 8h | 8h | 5h |
| JS/TS/React/浏览器面试 | 8h | 7h | 5h |
| Vue 3 岗位兼容 | 3h | 2h | 1h |
| 主项目工程化 | 9h | 8h | 6h |
| 可视化 / 3D 副线 | 0h | 2h | 10h |
| UI 与设计还原 | 2h | 3h | 3h |

如果每周只有 15 小时，保留投递 5h、面试基础与 Vue 兼容 5h、主项目 5h，暂停 3D；可视化只在 TaskFlow 的真实需求中顺带推进。求职成功前，3D/可视化/UI 合计不要超过总时间的 20%。

## 11. 是否学习热门技术的判断规则

每 8 周评估一次新技术，只在同时满足以下条件时投入：

1. 目标岗位中反复出现，或者旗舰项目确实需要。
2. 能在两周内做出可展示的小成果。
3. 不会挤占投递、面试基础和主项目质量。

近期建议：

- **应深入**：TypeScript、React、Next.js、测试、性能、可访问性、ECharts。
- **应集中补齐**：Vue 3、Pinia、Vue Router、Element Plus，以及 Vue/React 的核心差异。
- **条件性建立作品**：进入稳定面试流程或拿到 offer 后，再做 Three.js/R3F、Blender glTF 管线和 D3 定制作品。
- **应会使用**：Tailwind CSS、shadcn/ui、Storybook、TanStack Query。
- **先观察**：原生 WebGPU/WGSL、WASM、复杂微前端、自建 WebGL 引擎。
- **项目驱动再学**：AI SDK、流式输出、Web Worker、Monorepo、Docker。

## 12. 求职成功判定指标

未来 8 周至少达到：

- 160 个以上的有效投递，覆盖 React 与 Vue 3 业务岗位，并持续统计回复率和约面率，而不是只收藏岗位。
- 8 次以上技术面或模拟技术面复盘。
- TaskFlow 有在线演示、E2E、CI、性能报告和可访问性说明。
- 三个项目都能用“问题 - 方案 - 取舍 - 结果 - 改进”讲解。
- 能完成常见 Vue 3 业务代码阅读、修改，并回答与 React 的核心差异。
- 根据面试反馈至少完成 2 次简历、项目讲法或知识重点的调整，并观察后续转化变化。
- 根据招聘反馈调整简历关键词，而不是根据短视频热度换技术栈。

D3 和 Three.js 不属于前 8 周的硬性成功指标。最重要的执行原则：**你现在已经应该投递；学习必须服务于面试反馈或作品证据。** 先通过 React/TypeScript 与 Vue 3 业务岗位获得正式前端经历，再让 3D、可视化和 UI 成为未来 1-2 年持续累积的个人优势。
