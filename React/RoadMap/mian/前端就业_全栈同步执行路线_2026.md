## 1. 核心策略

### 1.1 定位

> 能独立交付 React/TypeScript 业务应用，熟悉 Next.js 与工程化，**具备 TaskFlow 上自建 Node/PostgreSQL 纵向交付能力**，并以数据可视化与 Web 3D（落在 U-s-cinema）形成差异化的前端工程师。

**不是：** 暂停前端转纯后端。  
**不是：** 同时开第四个 CRUD 仓库或独立 Three.js demo 长仓。  
**是：** 前端就业主场 + TaskFlow 一条后端补强线 + Cinema 一条 3D 产品线。

### 1.2 三项目唯一职责

| 项目 | 唯一主职责 | 同步学习落点 | 明确不做 |
| --- | --- | --- | --- |
| **TaskFlow** | 全栈主项目 | Fastify、PostgreSQL、Prisma、Session、测试、CI、最小部署 | 不为简历堆库；不先大改 UI 再补 API |
| **RedditLike** | 高级业务前端 | React 19、Tailwind 4、shadcn 试点、测试、a11y、性能、实时 UX | 不迁出 Convex/Clerk；不自建第二套后端 |
| **U-s-cinema** | Web 3D 代表作 | TS 事实一致、Three/R3F、影廊、降级、与收藏/详情联动 | 不做全站 Tailwind 重写；Gate B 前不自建电影业务 API |

### 1.3 同步学后端的三条铁律

1. **后端只服务 TaskFlow**（Gate B 前）。  
2. **必须纵向切片：** 页面操作 → 校验 → API → PostgreSQL → UI 反馈 → 至少一个测试。禁止连续两周只有 Postman。  
3. **后端时间从「主项目」块出，不另开第三条日常主线。** 前端 F1（面试基础）与投递不得被后端挤掉。

### 1.4 优先级（时间冲突时）

```
持续投递
  > 前端面试基础（F1）口述
  > TaskFlow 未闭合纵向切片
  > Cinema 3D（过门禁后的产品步）/ RedditLike 轮值质量
  > 可视化 Stats/D3 增强
  > Go / Redis / 新框架 / 旗舰新仓
```

## 2. 当前缺口与立即修正

### 2.1 求职向缺口（来自前端就业判断）

- 无正式前端经历 → 用**在线演示 + 测试 + 可讲清取舍**补可信度。  
- 测试偏工具函数 → 补关键用户流程（组件测 + E2E）。  
- 缺少量化 → Lighthouse/包体积/测试数等可验证指标。  
- 基础口述需系统化 → 每天 F1。  
- 特色代表作不足 → Cinema 3D 产品路径，而非四个散落 demo。

### 2.2 全栈向缺口

- TaskFlow 仍依赖 BaaS 心智 → 需自建 PG + 鉴权 + 归属。  
- Cinema 仓库可能与简历「TS strict」不一致 → **先核对事实再写简历、再开工影廊**。

### 2.3 投递前必改

- 修正「闲置物品互换平台」时间倒置（`2023.11 - 2023.04`）。  
- 主项目尽量提供在线地址/演示模式。  
- 无法连续回答 3 个追问的技术词降级或删除。  
- 项目描述强调难点、方案、约束、结果，少堆功能清单。

## 3. 固定技术决策（10–12 周内不摇摆）

### 3.1 就业前端核心

- JavaScript、TypeScript、HTML/CSS、React、Git、HTTP（每天练口述）。  
- Next.js、Vite、状态与表单（Zustand / 按需 Query）、Zod。  
- Vitest、Testing Library、Playwright、ESLint、CI、Web Vitals、a11y。  
- Vue 3 生态：能读能改能答差异，**不再做 Vue CRUD 新项目**。

### 3.2 全栈（仅 TaskFlow）

- API：Fastify + TS（Next Route Handler 仅 BFF/内部，不写第二套业务 CRUD）。  
- DB：PostgreSQL；ORM：Prisma（先懂关键 SQL）。  
- 认证：DB Session + HttpOnly Cookie + Argon2（JWT 只对比不双实现）。  
- 部署：最小在线优先；Docker 深挖 Gate B 后。

### 3.3 Web 3D（仅 Cinema）

- lab：`/lab/three` → 产品：`/experience` 或 `/cinema-3d`。  
- Three.js 基础 → R3F + Drei；glTF；降级与 DOM 等价路径。  
- **禁止**与 Cinema 脱节的长期 Three 独立仓库。

### 3.4 明确后置

- Go / Python / Java、Redis、BullMQ、Kafka、微服务、K8s。  
- 原生 WebGPU/WGSL、完整 3D 编辑器、大型数字孪生。  
- RedditLike 迁出自建后端、Cinema 全站 UI 重写。  
- Gate A 前的 TaskFlow Stats/D3 大升级（见时间线）。

## 5. 后端同步：学什么、做到什么

### 5.1 与前端面试强相关（优先）

用 TaskFlow 实战反哺口述：

- HTTP 状态码、Cookie、CORS、缓存  
- 「前端隐藏按钮 ≠ 权限」  
- 错误/加载/空态与 API 错误体一致  
- Zod 契约、类型与运行时校验  

### 5.2 Gate B 前 TaskFlow 必达

| 能力 | 验收 |
| --- | --- |
| PG 建模 + 迁移 + Seed | users/tasks/tags 等约束清晰 |
| 任务 CRUD/筛选/分页 | 浏览器真读写 |
| Session 登录注册退出 | Cookie 标志正确 |
| 资源归属 | 测过越权失败 |
| 核心 API 测试 8–12 | 含非法输入与约束失败 |
| Playwright 主路径 | 登录→创建→筛选→删除 |
| CI | lint / typecheck / test / build（+ E2E 可分 job） |
| Gate A-full | 公网或稳定预览 + 演示说明 |

### 5.3 不做（Gate B 前）

第二套认证（JWT 再实现一遍）、为 RedditLike 写后端、微服务、缓存队列、为「像后端」而迁出 BaaS 实时项目。

## 6. Cinema 影廊开工门禁

进入正式 `/cinema-3d`（或 `/experience`）产品交付前须全部满足：

1. 唯一主仓与主分支写入 `BASELINE.md`  
2. `build`（及现有 lint）可复现  
3. TS 状态核对：已有 TS 主仓并合并，或已启动 strict 渐进且核心模型有计划  
4. 简历与代码一致（未完成不写「已 strict」）  
5. Context 边界已记录（收藏/想看/详情如何被 3D 复用）  
6. `/lab/three` 最小场景可运行、resize、清理  

门禁前：只做 lab。门禁后：影廊 v1（选中→详情/收藏、懒加载、降级）。

## 9. 面试基础清单（F1，每天 45–90 分钟）

方法：先口述 → 最小代码 → 回到自己项目一句证据。

- **JS：** 作用域、闭包、原型、`this`、事件循环、Promise、模块、深浅拷贝  
- **TS：** 联合、收窄、泛型、条件/映射类型、`unknown`/`never`  
- **React：** 渲染、状态快照、Effect、闭包陷阱、Context、受控、性能  
- **浏览器：** 渲染流水线、事件、存储、同源、缓存、安全  
- **网络：** 方法、状态码、缓存、Cookie、CORS、HTTPS、WS/SSE  
- **CSS：** 盒模型、BFC、Flex/Grid、层叠、响应式、动画性能  
- **全栈口述（结合 TaskFlow）：** Session vs JWT、归属校验、SQL 注入防护、迁移意义  
- **3D 口述（结合 Cinema）：** 场景图、加载、R3F 与 React 状态边界、降级  

Vue：差异题够用即可（响应式、生态、和 React 对比）。

## 15. 最终执行原则

1. **你已经应该投递**；学习服务面试反馈或作品证据。  
2. **前端是锋刃，后端是 TaskFlow 上的边界扩展，3D 是 Cinema 上的差异化。**  
3. **每天 6h / 每周 40h：约 14h 全栈切片，约 20h 投递+F1+轮值前端，其余算法与缓冲。**  
4. **WIP≤2，双周轮换，熔断优先于硬扛。**  
5. **Gate A-min（6 周）→ A-full（≤8 周）→ 影廊（≤9 周）→ Gate B（12 周）。**  

> **持续投递 > 前端口述 > TaskFlow 纵向切片（含后端）> Cinema Web 3D 产品步 > RedditLike 工程质量 > 可视化增强 > 一切新技术。**
